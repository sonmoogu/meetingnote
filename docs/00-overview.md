## 화면

목록 · 넣기 · 상세 · 할 일, 총 4종.

- 배치와 요소 이름은 `docs/화면구성.pdf` 를 따른다.
- `id` 는 그 파일에 적힌 그대로 쓴다.
- 디자인: UI 는 맥OS 스타일, CSS 라이브러리는 Tailwind 로 깔끔하고 모던하게 만든다.

## 왜 이렇게 나누는가

관심사 분리(Separation of Concerns) 원칙에 따라, 한 문서는 한 가지 질문에만 답한다.

- 무엇을, 왜 만드는가 -> `01-product.md`
- 어떻게 동작해야 하는가 -> `02-specs.md`
- 어떤 구조로 만드는가 -> `03-design.md`
- 무엇을 할 것인가 -> `04-tasks.md`
- 어떤 규칙으로 쓰는가 -> `05-conventions.md`

이렇게 나누면 변경 이유가 서로 섞이지 않는다. 예를 들어 작업 순서가 바뀌어도 명세는 건드리지 않고, 설계가 바뀌어도 제품 정의는 그대로 둔다. 문서가 어긋났을 때 어느 문서의 어느 조항이 기준인지도 바로 가려낼 수 있어 유지보수가 쉬워진다.
